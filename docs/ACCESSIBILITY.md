# Accessibility

The interface targets WCAG 2.2 AA as an engineering objective. Automated and keyboard checks are release evidence; they do not establish complete conformance or independent certification. Report a barrier to [muhammadzahidulislam2222@gmail.com](mailto:muhammadzahidulislam2222@gmail.com) with the page, browser/assistive technology and expected interaction.

## Implemented interaction requirements

- Semantic headings, landmarks, buttons and real destination links; a skip link reaches main content.
- Mobile navigation uses a disclosure with expanded state, native links, Escape dismissal and focus restoration.
- Native dialogs cycle focus and restore their trigger; nested source inspection returns to the review context.
- Focus indicators remain visible on interactive controls, including dark pricing surfaces.
- Reduced-motion preference updates while the page is open: film is removed and smooth scrolling is disabled.
- Hero film can pause and stops offscreen/when the page is hidden.
- Responsive checks include narrow widths and maximum schema-valid imported text.
- Action errors and asynchronous status use readable text and appropriate live status.

Public-page checks scan every named route for serious/critical axe findings; the core suite checks all seven views. Keyboard journeys include navigation, dialog entry/escape/return and approval conflict. These checks passed in the verified release; see [release evidence](RELEASE-VERIFICATION.md).

## Images and content

Alt text depends on purpose. Informative images convey essential visible information; decorative images use empty alternatives; functional images describe the action. Long technical details belong in visible content. An image cannot establish wavelength, certification, medical suitability or other hidden product properties. [W3C image guidance](https://www.w3.org/WAI/tutorials/images/).

Complex evidence diagrams also need readable relationships or a textual equivalent. Error content should explain a recovery action. Do not rely on color or motion alone for status.

## Release review still required

Use keyboard-only operation, 200%/400% zoom and text reflow, high contrast, screen readers, touch target inspection, captions/transcripts for any future meaningful audio, and human review of generated descriptions. The expanded live application includes authenticated roles, uploaded-image purpose review and 120 original schematic cases. At the owner's request, an independent agent reviewed those cases; this is not independent human validation. Automated rules cannot judge every alternative text, reading order or cognitive barrier. [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [W3C preliminary checks](https://www.w3.org/WAI/test-evaluate/preliminary/).
