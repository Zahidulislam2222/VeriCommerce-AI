# Threat model

Scope: browser, public reverse proxy, API, PostgreSQL, worker, model cache, accounts, uploads, read-only Shopify, content review, approval/export and release artifacts. Current release `20261018-phase3-01` follows the integrated expansion `20261018-phase1-01` and the verified 2026-10-15 evidence release, with 228 matching artifacts and four verified healthy services. The final backend/infrastructure suite passed 140 checks; 46 live browser checks belong to the preceding expansion, with current store flows verified separately. This is a design review, not a penetration-test certificate or a claim that every external acceptance gate passed.

| Asset / threat | Implemented boundary | Remaining validation |
|---|---|---|
| Another workspace's evidence | Cookie identity, verified account membership, transaction-local tenant context, forced RLS and scoped lookup | Repeat two-tenant/four-role matrix after schema/query changes; host administrator remains trusted |
| Cookie theft / forged write | Separate HttpOnly/Secure/SameSite account/temporary cookies, token hashes, exact Origin and JSON writes | XSS/CSRF, expiry and proxy trust verification; HttpOnly does not prevent authenticated actions through XSS |
| Stale-tab or revoked membership write | Optional expected-workspace header; mutations recheck permission under the tenant lock | Verify competing workspace selection/revocation and keep browser data keyed to selected workspace |
| Account guessing / password CPU exhaustion | Salted scrypt, per-address attempts, account/session quotas and bounded password concurrency | Real abuse/overload assessment; email verification and automated recovery remain absent |
| Injection in imported text | Typed imports and parameterized SQL; retrieved text remains data without tool authority | Quotations can still repeat false/hostile source content; future model tools require independent authorization |
| Malicious documents / decompression bombs | Bounded upload bytes/storage; disposable resource-limited parser; strict MIME/static raster checks; active/encrypted PDF rejection; bounded JSON IPC without unpickling | Parser dependency review and actual adversarial file tests; process limits are not a complete operating-system isolation boundary |
| Unsupported publication | Evidence-only drafts, version checks, approval/export | Shopify publishing is absent; later credentials must sit outside model tools |
| Stale or repeated work | Immutable evidence, source generations, tombstones, stale invalidation and leased attempt fencing | Publishing still requires remote-write reconciliation; receipts do not establish distributed exactly-once execution |
| Removed variant evidence reused | Stable provider children, product/source tombstones, pre-model constraints and dependent approval invalidation | Exercise removed/re-added/deleted/uninstalled lifecycle and historical access policies |
| Exhausted CPU/database/disk | Body/rate/catalog/job/upload bounds, parser limits, fair worker scanning and CPU model lock | Adversarial load profile and overload telemetry; quotas do not prove serving capacity |
| OAuth substitution / credential leakage | Expiring browser/session/workspace-bound state, HMAC callback, verified shop identity, exact read scope and encrypted tenant/shop-bound tokens | Real OAuth/read-only scope and initial 61-product sync verified; actual incremental delivery and refresh/reconnect acceptance remain separately gated; protect settings/backups/key rotation |
| Forged/replayed/out-of-order webhook | Raw-body HMAC, durable receipt/effect transaction, duplicate identity checks, timestamps and ordered product tombstones | Verify actual provider delivery and bounds; local fake-provider tests do not prove live webhook setup |
| Cross-variant model exposure | Current-only centralized product/SKU/color/category eligibility before embedding | Repeat exact SKU/parent/variant and mismatched-constraint suites against imported catalogs |
| Image used as technical authority | Observations stored separately; purpose contract, critical-term rejection and identified approval | Human accessibility acceptance remains pending; keyword guards are not general semantic claim verification |
| Incorrect structured data | Deterministic source-backed offers/variants and visible metadata checks; missing/conflicting evidence blocks output | Authoritative inputs can themselves be wrong; no search-placement guarantee |
| Compromised dependency/model | Hash locks, pinned image/model revision, controlled download | Dependency monitoring, release SBOM and reproducible rebuild checks |
| Backup exposure / loss | Authenticated encrypted off-server archive; actual populated restoration matched all 26 tables with restricted-role isolation and primary unchanged; rollback/forward preserved three approved drafts and volumes | Rehearsals do not establish scheduled backups, retention, operational key rotation or continuous RPO/RTO compliance |
| Host administrator compromise | Separate containers/roles and no runtime admin DSN/socket | Host/root remains trusted; isolation cannot protect from a fully compromised host |
| Browser cache / cross-tenant reuse | Private no-store API responses, expected-workspace binding and current-only context snapshots | Any future shared result cache must key tenant/permissions/source/model/policy versions |
| Synthetic evaluation overstated | Integrity-bound family split, exact item review coverage and separate agent/human states | Agent review is not human validation; local fixtures are not merchant quality or cloud deployment evidence |
| Optional cloud adapter exposure/cost | Actual sanitized Azure Free reference, bounded authenticated AWS validator/four initial plus four final-source invocations, and three successful IAM-authenticated GCP synthetic smoke cases; GCP temporary resources removed before deadline with 135 baseline payloads unchanged | These contracts do not prove held-out model quality; final billing remains unverified, and inventory/allowances/shutdown evidence must be maintained; credits do not cap paid-account exposure |

Trust boundaries are crossed at the public request, cookie-to-membership mapping, database connection, worker claim, disposable parser IPC, model artifact download, Shopify transport/webhook and release promotion. A source citation establishes lineage, not truth; malicious or incorrect source documents can still produce incorrect evidence-backed quotations. Source deletion and store-data retirement exclude current evidence but do not promise erasure of retained revisions/citations or backups.

Prompt injection is limited today because retrieved text does not execute tools. Future generative workflows must authorize tool arguments and publishing in application code, restrict egress and test hostile documents/images/tool results. Do not rely on an instruction asking a model to ignore malicious text. [OWASP prompt injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/).

Session controls follow standard cookie guidance but require actual configuration and browser checks. HttpOnly reduces script access to tokens; it does not remove XSS impact. [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

The deployed application implements roles, account sessions and integration-token encryption, but their existence is not a complete merchant-service security program. Automated recovery/email verification, operational key rotation, retention/deletion requests, processor agreements, abuse monitoring, incident notification and independently reviewed accessibility/upload behavior require explicit operational acceptance. Shopify publishing and public-app distribution are later boundaries; applicable privacy-webhook and distribution requirements cannot be inferred from this catalog-only connector.
